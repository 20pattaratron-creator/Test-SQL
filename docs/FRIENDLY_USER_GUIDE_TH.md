# คู่มือใช้งานแบบ Friendly สำหรับผู้เริ่มต้น

เอกสารนี้ออกแบบสำหรับผู้ที่ไม่เคยใช้ SQL, MySQL, Tableau หรือ Power BI มาก่อน แต่ต้องการใช้เว็บนี้เพื่อวิเคราะห์ข้อมูลและดูคำแนะนำทางธุรกิจ

## แนวคิดหลัก

ผู้ใช้ไม่จำเป็นต้องเขียน SQL ตั้งแต่แรก ระบบรองรับการใช้งานแบบกดเลือกได้:

1. กดสร้างข้อมูลตัวอย่าง หรืออัปโหลด CSV
2. เปิด Dashboard เพื่อดู KPI และกราฟ
3. เปิด Business Analytics เพื่อดูข้อเสนอแนะว่า “ควรทำอะไรต่อ”
4. ตรวจ Data Quality เพื่อดูค่าว่างและข้อมูลซ้ำ
5. ใช้ SQL Editor เฉพาะเมื่ออยากวิเคราะห์เชิงลึก

## โหมดสี

ระบบมี 2 โหมด:

- โหมดสว่าง: ค่าเริ่มต้น เหมาะกับผู้เริ่มต้นและการใช้งานกลางวัน
- โหมดมืด: เหมาะกับการทำงานกลางคืนหรือลดแสงหน้าจอ

ธีมหลักยังคงเป็นสีน้ำเงิน เพื่อให้ดูสะอาด เป็นมืออาชีพ และเข้าใจง่าย

## ขั้นตอนเริ่มต้นเร็วที่สุด

1. เปิดเว็บ
2. กดปุ่ม “ลองด้วยข้อมูลตัวอย่าง” หรือ “เริ่มด้วยข้อมูลตัวอย่าง”
3. ระบบจะสร้างตาราง `sales_data`
4. เปิด Dashboard เพื่อดูยอดขาย กำไร และกราฟ
5. เปิด Business Analytics เพื่อดู Recommendation & Action Plan

## ถ้ามีไฟล์ CSV ของตัวเอง

เตรียมไฟล์ให้มีหัวตาราง เช่น:

```text
order_date, customer_id, product_name, category, region, channel, quantity, unit_price, discount, cost
```

หรือถ้ามีคอลัมน์ที่คำนวณมาแล้ว ระบบจะใช้ได้ทันที เช่น:

```text
net_sales, profit, gross_sales, total_cost
```

ระบบจะพยายามเลือกคอลัมน์ให้อัตโนมัติจากชื่อคอลัมน์ เช่น:

- sales, revenue, amount, net_sales = ยอดขาย
- profit, gross_profit = กำไร
- order_date, date, created = วันที่
- category, region, channel = กลุ่มข้อมูล
- customer_id, customer = ลูกค้า
- product_name, product, sku = สินค้า

## คำแนะนำการตั้งชื่อคอลัมน์

เพื่อให้ระบบใช้งานง่ายที่สุด ควรใช้ชื่อตามนี้:

| ความหมาย | ชื่อคอลัมน์ที่แนะนำ |
|---|---|
| เลขคำสั่งซื้อ | order_id |
| วันที่สั่งซื้อ | order_date |
| รหัสลูกค้า | customer_id |
| ชื่อลูกค้า | customer_name |
| รหัสสินค้า | product_id |
| ชื่อสินค้า | product_name |
| หมวดสินค้า | category |
| พื้นที่ | region หรือ province |
| ช่องทางขาย | channel |
| จำนวน | quantity |
| ราคาต่อหน่วย | unit_price |
| ส่วนลด | discount |
| ต้นทุนต่อหน่วย | cost |
| ยอดขายสุทธิ | net_sales |
| กำไร | profit |
| สถานะคำสั่งซื้อ | order_status |

## หน้า Dashboard ใช้ทำอะไร

ใช้ดูภาพรวมอย่างรวดเร็ว เช่น:

- ยอดขายรวม
- กำไรรวม
- Profit Margin
- จำนวนลูกค้า
- แนวโน้มรายเดือน
- ยอดขายตามหมวดสินค้า/พื้นที่/ช่องทาง
- ลูกค้าซื้อสูงสุด

เหมาะกับคำถาม: “ธุรกิจภาพรวมเป็นอย่างไร?”

## หน้า Business Analytics ใช้ทำอะไร

ใช้ช่วยตัดสินใจทางธุรกิจ เช่น:

- เดือนล่าสุดยอดขายโตหรือไม่
- หมวดใดสร้างรายได้สูงสุด
- สินค้าใดขายดีแต่กำไรต่ำ
- ลูกค้ากลุ่มใดเสี่ยงหาย
- ควรโปรโมตสินค้ากลุ่มใด
- ควรลดต้นทุนหรือปรับส่วนลดตรงไหน

เหมาะกับคำถาม: “ข้อมูลชุดนี้แนะนำให้เราทำอะไรต่อ?”

## หน้า Data Quality ใช้ทำอะไร

ใช้ตรวจว่าข้อมูลพร้อมวิเคราะห์หรือยัง เช่น:

- มีค่าว่างกี่ช่อง
- มีข้อมูลซ้ำหรือไม่
- จำนวนแถวทั้งหมด
- ตัวอย่างข้อมูลจริง

ควรตรวจหน้านี้ก่อนนำผลลัพธ์ไปใช้ตัดสินใจจริง

## หน้า SQL Editor ใช้เมื่อไร

ใช้เมื่อผู้ใช้ต้องการถามคำถามเฉพาะ เช่น:

- Top 10 ลูกค้าจากยอดขาย
- ยอดขายรายเดือน
- กำไรตามหมวดสินค้า
- รายการที่สถานะไม่ Completed

ผู้ใช้เริ่มจากปุ่มตัวอย่าง SQL ได้ ไม่ต้องจำคำสั่งเองทั้งหมด

## ข้อควรระวัง

- GitHub Pages ใช้ได้เฉพาะ frontend และ SQLite ใน browser
- ถ้าต้องต่อ MySQL จริง ต้องใช้ backend เช่น Vercel API / Render / Railway / VPS
- อย่าใส่รหัสผ่าน MySQL ในไฟล์ `app.js` หรือหน้าเว็บ
- ข้อมูลที่เป็นข้อมูลบริษัทจริงควรมี Login, HTTPS และสิทธิ์ผู้ใช้
